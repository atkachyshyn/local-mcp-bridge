# Final verification review — Local MCP Bridge v0.8

You have repository access to **Local MCP Bridge POC v0.8**. This is a narrow verification gate after the v0.7 final review. Do not redesign the product or reopen already-settled architectural choices unless the implementation now contradicts them.

## Prior verdict

The v0.7 gate returned `PROCEED WITH BLOCKERS` with two blockers:

1. **B1 — root containment was key-name based.** Absolute paths under keys such as `filename`, `dest`, `target`, `output`, `pcb`, `src`, `to`, etc. could bypass daemon `roots`.
2. **B2 — auto-start looked only at the latest assistant message.** A later user countermand could be ignored after reload/new tab, allowing a never-executed task to auto-start.

The same review also asked for these small fixes in the same sitting:

- do not process the latest assistant host while it is still streaming;
- tolerate harmless composer whitespace normalization while still proving the composer contains exactly one bridge-generated `LBP_RESULT` and no extra user text;
- validate a one-time approval token before consuming it;
- scope Send-button lookup to the verified composer's form;
- warn clearly about policy-only writes and unattended destructive execution;
- make session-approval wording show the real scope/duration;
- optionally harden tab-duplication/session scope and bind approval to classification;
- reject deprecated model-authored `mutating` / `required` fields in the browser parser instead of silently stripping them.

v0.8 claims to close all of the above while keeping LBP 1.1 single-operation and keeping auto-continuation outside the protocol.

## Review goal

Return one of:

- `READY FOR CONTROLLED USE`
- `READY WITH IMPORTANT FOLLOW-UPS`
- `PROCEED WITH BLOCKERS`
- `REDESIGN`

The bar for `READY FOR CONTROLLED USE` is: safe enough for one technically capable user to use against explicitly configured local MCP servers, including controlled source-code mutations, with `approval_mode=mutations` and optional browser auto-continue.

## 1. Reproduce B1 against v0.8

Do not inspect only the diff. Attack the running daemon/mock MCP path.

Configure one allowed root and an allowed write tool. Attempt outside-root absolute paths under at least:

- `path`
- `filename`
- `dest`
- `target`
- `output`
- `pcb`
- `sch`
- `src`
- `to`
- nested object/list values
- a `~`-prefixed value that expands outside the root

Verify every path-like value is denied before MCP dispatch.

Also verify:

- an in-root absolute path under an unknown key is allowed;
- a relative value under a recognized path key fails closed;
- an absolute path with `roots=[]` fails closed;
- ordinary non-path strings are not spuriously treated as paths in normal MCP payloads.

If you find a false-positive class likely to break `apply_patch` / source editing, report it explicitly.

## 2. Reproduce B2 against the browser adapter

Trace or exercise these sequences:

### Countermand

1. assistant emits a complete valid LBP task;
2. user sends `don't run that` or another normal message;
3. reload / reopen / rescan;
4. confirm the older assistant task cannot auto-start.

### Latest assistant

1. user's normal prompt;
2. assistant emits a valid task and becomes the conversation's last message;
3. confirm it can auto-start when local policy permits.

### Streaming

1. assistant is still generating;
2. one complete LBP task happens to appear before generation ends;
3. later text adds a second task or changes the envelope;
4. confirm the streaming host was never marked processed/executed from the partial snapshot.

The relevant invariant should now be: **auto-start only on a completed assistant message that is also the latest conversation message overall**.

## 3. Attack composer auto-submit again

Verify all of these:

- normal ProseMirror/newline normalization does not make auto-continue fail unnecessarily;
- exact user-authored extra text still causes failure/stop;
- exactly one `<LBP_RESULT>` and one closing marker are required;
- two result envelopes are refused;
- composer is checked immediately before Send;
- Send is resolved from the verified composer's own enclosing form;
- if no safe form/Send exists, it pauses rather than clicking a document-global control;
- a user draft can never ride along with an automatically submitted tool result.

## 4. Attack approval/token/session refinements

Verify:

- wrong-session use of a valid one-time token fails **without consuming the token**;
- the subsequent correct task/session use succeeds;
- wrong task digest fails without consuming the token;
- policy change invalidates the token;
- tool classification mismatch invalidates the token;
- successful use consumes the token exactly once;
- session leases are still risk-tier bounded (`read < write < destructive`);
- session lease lifetime is now roughly 2 hours, not 12;
- duplicated tabs / different conversations do not silently reuse the same effective daemon session scope if the new service-worker scoping is intended to prevent that.

## 5. Inspect dangerous-policy UX

Verify that the settings UI now makes these configurations conspicuous:

- `approval_mode=none + write=true`;
- `approval_mode=none + write=true + auto_continue`;
- `allow_destructive=true + always_approve_destructive=false`;
- `write=true + roots=[]`.

Confirm saving policy-only writes requires a deliberate typed confirmation rather than a normal click.

Confirm the session approval button communicates what it really grants, e.g. all writes/reads to a named server for the configured lease duration, rather than the vague `Allow for session` wording.

## 6. Confirm protocol/authority invariants did not regress

Re-run spot checks that:

- LBP is still exactly one operation;
- model text cannot set approval mode, roots, allowed tools, continuation mode, mutation classification, or leases;
- `mutating` and `required` are rejected in both browser normalization and daemon normalization;
- bridge-native shell/filesystem execution has not returned;
- MCP server/tool allowlists remain deny-by-default;
- `status:"unknown"` mutation state is never auto-retried;
- auto-continue remains browser behavior, not a model-authored LBP field.

Run at minimum:

Inspect the new smoke coverage rather than trusting a green result. It should specifically cover the v0.7 root-key bypass vocabulary, `~` expansion, relative recognized-path rejection, empty-roots behavior, normal non-path payloads, approval-token non-consumption on failed task/session binding checks, and permanent invalidation on policy change. `browser_smoke_test.js` should cover the adapter's single-result normalized composer matching, last-message lookup, and pre-Send recheck.

## 8. Final answer format

Please give:

1. **Verdict**
2. **Remaining blockers**, if any
3. **Important follow-ups** that do not block controlled use
4. **Verified fixes** for B1 and B2
5. **Security boundary assessment** for `approval_mode=mutations + auto_continue`
